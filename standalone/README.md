# standalone/ · 单文件构建产物

这个目录里**只有构建产物，没有源码**。

## 它是什么

`seek-web.standalone.html` 是把整个模块化前端**内联成的一个 HTML 文件**：

- 9 个 CSS（`styles/*.css`）
- 19 个 ES Module（`js/**/*.js`）
- 页面结构（`index.html`）

全部塞进一个文件，所以：

| 能做 | 不能做 |
|---|---|
| ✅ 双击直接打开（`file://` 也能跑） | ❌ 直接改这个文件 |
| ✅ 发给别人 / 离线演示 | ❌ 当成源码提交修改 |
| ✅ 单文件归档 | ❌ 在这里找模块结构 |

## 为什么它必须存在，但只有源码要维护

浏览器禁止 `file://` 页面用 `import` 加载本地模块，
所以模块化版本必须开 HTTP 服务器才能看。
单文件版就是为了「不想开服务器、只想看一眼」的场景。

**但它是生成的**，跟源码是同一个东西的两种形态：

```text
源码（唯一要维护的）                      产物（自动生成）
index.html + styles/ + js/ + config/  →  standalone/seek-web.standalone.html
```

改功能请改源码，然后重新生成。

## 怎么重新生成

```bash
node tools/build-standalone.mjs
```

打包器会：

1. 从 `js/main.js` 出发解析相对 `import`，做拓扑排序
2. 剥掉 `import` / `export` 语法，按依赖顺序拼接
3. **用 `vm.Script` 编译校验**合并结果 —— 顶层重名会直接报错，不会静默出错
4. 内联 CSS 与 JS，并做构建后自检（无残留外链、`$$` 等符号未被破坏）
5. 在文件顶部插入「请勿直接修改」警示

## 和线上版本的关系

| 版本 | 入口 | 用途 |
|---|---|---|
| 模块化 | 根目录 `index.html` | **部署到 GitHub Pages、开发** |
| 单文件 | `standalone/seek-web.standalone.html` | 本地双击查看、分享、归档 |

两者**行为一致**（单文件版就是从同一份源码打包出来的），但只有模块化版本会被部署。
